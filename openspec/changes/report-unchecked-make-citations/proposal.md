# Change: Report Unchecked `make` Citations (R4 + R5)

## Why

G004 is the mechanical form of this project's headline claim — a spec that
cites a gate the repository does not have fails the build. In two distinct
situations it reports nothing while believing itself correct, and in both the
CLI throws away the fact that the check did not run.

**Part 1 — G004 discards the fact that it could not run.**
`openspec_graph/rules_generic.py`'s `_unknown_make_target` opens with

```python
if not profile.make_targets:
    return
```

so a target repository whose Makefile `detect` did not find passes G004
vacuously, and `cmd_validate` prints `PASS` with zero findings — even at
`--fail-on INFO`, which is the setting a caller chooses precisely to see
everything the run knows. The composite Action computes the same fact
independently: `openspec_graph/report.py`'s `discovery_notes()` produces the
`discovery-warnings` output declared in `.github/actions/planlint/action.yml`,
and its own docstring already concedes that a green run over such a repository
"proves less than it looks like it proves". The CLI — which pre-commit,
`make validate` and every agent invocation use — says none of that.

**Part 2 — the five most-cited stage names are exempt even when Make is
demonstrably in use.** `openspec_graph/rule_types.py` declares
`GENERIC_STAGES = {"ci", "test", "validate", "lint", "coverage"}` and the same
function skips any citation naming one (`target not in GENERIC_STAGES`). The
exemption is not a bug on its own: a repository driven by tox, npm scripts or
`just` may write "run `make test`" as ordinary English shorthand, and flagging
that would false-positive on prose. That argument holds exactly when the
repository does not demonstrably use Make — and the profile already knows which
kind of repository it is looking at.

**Evidence:** reproduced at `c60f894` and tabulated in
`docs/peer-review-2026-09.md` (F2, F3, D2, D3.2). Against a Makefile declaring
only `build`, a citation naming `regression` yields 1 G004 finding while each
of `test`, `ci`, `lint`, `coverage` and `validate` yields 0. The tool also
generates the exempt case itself: `openspec_graph/scaffold.py`'s `pick_stage()`
returns `"test"` when `profile.make_targets` is empty, so `planlint new`
scaffolds a citation naming `test` five times into a repository where the rule
is switched off anyway. The same review files these two as **R4** ("INFO
finding when a rule skips for want of machinery") and **R5** ("WARN on a
generic-stage citation when Make *is* in use") in its rewritten-remainder
table.

## What Changes

- `openspec_graph/rules_generic.py`: two new per-spec checks and two new
  `Rule(...)` entries in `GENERIC_RULES`.
  - **G010 (INFO)** — a spec carries at least one `make` citation and
    `profile.make_targets` is empty: one finding per spec recording that the
    cited-stage check could not run, and that the pass is about spec
    well-formedness rather than about stages this repository runs.
  - **G011 (WARN)** — `profile.make_targets` is non-empty and a citation names
    a `GENERIC_STAGES` member that is absent from it: one finding per offending
    citation.
  - `_unknown_make_target` (G004) itself is **not** edited — neither the
    empty-`make_targets` guard nor the `GENERIC_STAGES` exemption moves.
- `openspec_graph/rule_types.py`: `GENERIC_STAGES` gains a docstring-level
  comment pointing at G011, so the exemption stops being undocumented (the
  review's R2, absorbed here because G011 is the thing that documents it).
- `openspec_graph/rules.py`: module docstring's `rules_generic` family range
  becomes `G001-G011` (`tests/test_rule_registry_docs.py` enforces this).
- `tests/test_rule_registry_docs.py`: `test_readme_rules_table_matches_rules_exactly`'s
  `(ERROR|WARN)` alternation widens to include `INFO`. G010 is the first
  INFO-severity entry in `RULES`, and the guard is blind to such a row today —
  it would fail with a "missing/extra" message that names no cause.
- `tests/baseline_rules.json`: regenerated from `planlint rules --json`.
- `skills/planlint-spec-governance/references/rule-catalog.md`: regenerated by
  `make skill-catalog` (generated artifact, never hand-edited).
- `README.md`: two rows in the rules table; the severity sentence above it
  gains an `INFO` clause; the "no Makefile and no coverage floor" paragraph
  stops saying the Action is the only place that reports it.
- `docs/architecture/c4.md`: the `rules.py` rule count and the
  `rules_generic.py` family range in the module map.
- `docs/agents-skills-harness.md`, `docs/next-steps.md`,
  `docs/differentiation-roadmap.md`: the rule-count claims each guards.
- `openspec_graph/report.py`: `discovery_notes()`'s docstring stops recording
  the CLI's silence as correct; its computed value and the Action's
  `discovery-warnings` output are unchanged.
- `tests/test_graft.py`: fixtures and assertions for both new rules, the
  no-double-report partition across G004/G010/G011, and the waiver path.
- `CHANGELOG.md`: an `Unreleased` entry closing the two ledger items this
  change answers.

## Non-Goals

- **Which filenames `detect` searches for.** `GNUmakefile` and lowercase
  `makefile` going undiscovered is the review's F1/R1 — a separate package.
  It is the *reason* many repositories reach Part 1's empty-`make_targets`
  path, but fixing discovery and reporting an unrun check are independent, and
  bundling them would make it impossible to tell which one closed a given
  vacuous pass.
- **Anything about SpecKit parsing.** The wrong-level-heading data loss (F4/R6)
  is its own defect with its own rule family.
- **Widening the Action's `indeterminate` status.** That is D3.3/R8, an
  explicitly deferred policy question, and this change is the prerequisite that
  makes it smaller rather than the change itself.
- **Re-projecting `discovery-warnings` from findings.** `discovery_notes()`
  also covers the coverage-floor case, which has no corresponding rule id;
  deriving half of the output from the envelope would leave two inconsistent
  derivations instead of one. See DEC-UMC-007.
- **Changing what `planlint new` scaffolds.** `pick_stage()`'s `"test"`
  fallback for a Makefile-less target stays. After this change the scaffolded
  package's own INFO finding says plainly that the citation was not checked,
  which is the honest fix; changing the emitted text is a separate question.
- **Deleting or narrowing `GENERIC_STAGES`.** The exemption survives intact for
  the repositories it was written for. G011 is conditioned on the repository
  demonstrably using Make, which costs nothing in the tox case because such a
  repository has no Makefile and never reaches the check.
- **No change to G004's id, severity, dialect set, message, or guard clause**,
  and no new entry in `rules._NON_WAIVABLE`.
